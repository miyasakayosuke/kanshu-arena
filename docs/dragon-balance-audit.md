# ドラゴン v0.12 バランス検証

日付: 2026-10-10 UTC。親タスクが中核HP220・竜気係数18・ID17連撃威力20・ID18固定基礎68を採用し、その最終ソースで再検証した。公開操作は行っていない。対人戦の均衡や最適行動の証明ではなく、前の獣・自然監査は変更しない。

## 条件と比較の意味

- 本番 `advanceWithEvents` で解決し、両軍に同じ既存 `autoOrders` を使う。通常ゲームの敵CPUは変えない。
- 固定32シード（生成基準20261010）、左右を入れ替え、baseline/candidateの両版、全編成ミラーを含む。固定13編成・40対面・13ミラーで各6,784戦。
- 幅の確認は、結果を見る前に固定した24生成非中核編成を8対策編成へ加え、5対象のすべてと対戦。16シード、37編成・160対面・37ミラー、12,608戦。実使用率や最適編成の母集団を代表しない。
- 純竜 `[15,5,16,17,18]` COST17、3竜混成 `[15,16,18,2,10]` COST15、発動しない2竜混成 `[15,16,3,2,10]` COST15、中核だけ玄武へ同COST置換 `[14,5,16,17,18]` COST17、同5体の非中核リーダー `[5,15,16,17,18]` COST17。
- 対策8編成は旧全獣 `[12,0,2,11,13]`、旧全自然 `[14,3,6,9,10]`（元の毒3体を保持）、先制、毒＋清め、守護＋回復、解除技所有、全体攻撃、長期戦のMP支出圧力。最後の群にMP吸収・MP直接減少技はない。技所有だけを実行した対策と呼ばず、実際のイベント指標を読む。
- 玄武置換は個体・技・対象リーダー・自然障壁も変わる。竜気だけの因果比較は `dragonCharge.enabled:false` と `perPoint:0` の別候補で扱う。
- `autoOrders` は指示時点の竜気だけで評価する。同ターンの味方の攻撃で後から増える値を予測しない。人間の手動指示の最善手や楽しさの証明として使わない。

## 開発Labの追加

`overrides.dragonCharge` は `enabled`（真偽）と `perPoint`（0～100の整数）のみ。空のオブジェクトや無関係の能力値変更で竜気が失われない。開始5枠のパッチ後の系統から両側で資格を計算し、中核ID15＋開始時竜3体以上の軍だけ中核へ0を置く。

全系統IDは `src/families.ts` を共有。`fixedDamage` / `dragonChargeFinisher` は厳密な真偽値検証を行う。固定基礎は攻撃技のみ、竜気解放は有料・固定基礎・全体・アンカー技に限定する。MP、守り、乱数、自然障壁の本番処理は保持する。

竜気0～5の整数、無効な枠が有効にならないこと、中核以外に付かないこと、KO後は0、検証用係数の不変、イベントの絶対値とターン終了状態の一致を毎ターン確認する。通常/失敗トレースのスナップショットには存在する場合だけ竜気/係数を残す。CLIは従来のエンジン・Lab・設定に加え、共有系統ソースのSHA-256も照合する。

竜気の実増加、消費、解放回数、正の竜気を使った解放回数、解放の直接ダメージ、相手の竜気を解除した量、自軍がKO時に失った量、試合中ピークをMPとは別に集計する。上限で増えなかった試行は実増加に含めない。中核の解放前死亡は試合終了時死亡かつ解放0回として保存済み単体指標から計算する。

## 名簿拡大時の編成生成

20体以下では従来の合法5体集合の列挙とシャッフルを保持し、既存の小名簿の抽出順を変えない。21体以上では、残り枠数と両候補の残りCOSTを持つ動的計画で合法な後続集合数を正確に数える。次にシード付きの開始順位と、集合総数と互いに素な歩幅で異なる合法順位をたどる。

37体で全5体組を格納せず、費用上限17・5枠に対する状態数で計算量を制限する。必要な取得数＋除外集合数までの順位訪問で目的数に達する。除外を引いた合法数が不足なら、数を黙って減らさず明示的に失敗する。候補/基準の双方で合法、重複IDなし、固定集合との重複なしを確認する。

これは一様無作為抽出の証明ではない。LCG、順位歩幅による相関、編成枠シャッフル、固定対象への循環割当てに偏りがある。今回の幅確認では24編成を設定へ明示保存し、各対象にすべて当てることで循環割当てを使わない。将来37体になっても、合法な全対面やリーダー位置を網羅したことにはならない。

原始ログ、対象ごとの勝敗・支援・MP・竜気、出典ハッシュは `dragon-balance-summary.json` および記載のCLI出力を参照。初期ソースのコピーは未追跡の `lab-results/dragon-initial-source/` に保管。`dragon-initial-values.json` は後の最終ソースで初期数値を明示復元する比較用であり、異なるコードを当時の完全再生と呼ばない。

## 仲間の効率と解放係数の感度（探索）

中核HP220・係数14を保持し、ID17の連撃威力12→20、ID18の固定基礎57→68だけを変更した候補は、固定群で純竜129勝・13引分/512、得点率26.46%。係数18にすると256勝・13引分/512、51.27%。3竜混成はそれぞれ6.25%、13.48%。同じ仲間・HPを保って竜気だけ無効にすると純竜2勝/512、0.39%。無効時は係数自体が働かないので14と18の無効化対照は同一である。

係数18の純竜得点率は全獣50%、全自然0%、先制76.56%、毒＋清め87.5%、守護回復56.25%、解除78.13%、全体46.09%、MP支出圧力15.63%。平均だけから全対面の均衡を主張しない。全自然の元の3毒を残した上で、明確な苦手として記録する。

係数14の幅確認は、生成24編成だけで397勝・3引分/768、51.89%。固定8編成も含むと453勝・10引分/1,024、44.73%。生成相手のうち2/24に全勝する一方、7/24へ10%以下であり、普遍的な勝利ではない。係数18の幅確認と採用後の最終ソース検証は次節に記録する。

## 採用値の最終ソース検証

最終値は中核HP220（竜HPリーダー適用後242）、MP62、ATK31、SPD44、竜気係数18。解放は固定基礎10＋竜気×18で、上限5なら基礎100/対象、MP28、アンカー。ID17のランダム2連撃だけ威力20、ID18の単体固定基礎だけ68。その他の既存個体・通常ゲームCPUをこの検証で変えていない。

固定8対策・32シードの各対象結果は次の通り。得点率は `(勝ち＋0.5×引分)/試合数` で、引分を勝ちと数えない。

| 対象 | 勝ち | 引分 | 試合 | 得点率 |
| --- | ---: | ---: | ---: | ---: |
| 純竜・中核リーダー | 256 | 13 | 512 | 51.27% |
| 3竜＋混成支援 | 69 | 0 | 512 | 13.48% |
| 2竜・竜気不成立 | 18 | 0 | 512 | 3.52% |
| 中核だけ同COST玄武へ置換 | 0 | 0 | 512 | 0% |
| 同5体・ケツァルコアトルリーダー | 165 | 8 | 512 | 33.01% |

純竜の8対面内訳は、獣32勝/64、自然0勝/64、先制48勝2引分/64、毒＋清め56勝/64、守護回復36勝/64、解除50勝/64、全体24勝11引分/64、MP支出圧力10勝/64。自然の原来の毒3体を減らさず残す。強い相手を除いて「50%前後」とする解釈はしない。

純竜は平均4.369ターン、MP155.617消費/試合、手持ち有料技を一つも使えない生存個体ターン1.283、竜気実増加6.420、消費4.391、解放0.926回。中核が一度も解放せず死ぬ試合38/512（7.42%）、中核が一度も行動せず死ぬ試合0。単体最大の直接ダメージ分担率は平均44.86%で、支援の価値まで示す因果指標ではない。

竜気だけ無効にすると純竜2勝/512、0.39%。係数0では蓄積表示・イベント自体は残るが、無効化版と全3,392試合の勝敗・ターン・最終HP/MP・行動数・直接ダメージが一致した。新しい個体の素の能力だけで勝っているとはいえず、竜気が実際に勝ち筋へ寄与する。一方、3竜混成は発動条件を満たすことと高効率であることが別である。

### 凍結した24非中核編成への幅確認

最終純竜は生成編成だけで531勝・11引分/768、得点率69.86%。固定8編成を加えると653勝・21引分/1,024、64.79%。3竜混成は生成264勝/768、34.38%、全体302勝/1,024、29.49%。非中核リーダーは全体524勝・6引分/1,024、51.46%。玄武置換は全体2勝/1,024。

純竜は生成6/24編成へ100%、11/24編成へ90%以上。一方、`generated-8` `[10,9,13,8,4]`（COST13）には0勝・6引分/32、9.38%、`generated-23` `[1,4,9,7,16]`（COST15）には0勝/32で、万能ではない。

生成側のCOSTは12～17で、純竜は17。12:1編成、13:4、14:5、15:7、16:5、17:2という分布のため、69.86%を同コスト総当たり勝率と呼ばない。同COST17の生成2編成に限ると28勝/64、43.75%だが、2編成だけなので推定範囲は狭い。

### 再現性・回帰確認

- 最終ソースの `identity`、`charge-disabled`、`charge-zero`、`initial-values` は各6,784戦、`broad` は12,608戦、smokeは736戦。合計40,480戦で不変条件違反なし。
- `identity` は全対面のbaseline/candidate結果が一致し、非ミラー2,560対応で変更0。幅確認のidentityも変更0。物理味方側ミラー得点率は固定群50.36%、幅群48.65%。左右交換で必然的に50%となる正規化ミラー値を公平性の根拠にしない。
- `initial-values` 候補は保存済み初期baselineの3,392試合と勝敗・単体/軍指標がすべて一致（traceHashを除く）。上書きやソースが違うため、当時の完全トレース再生とは区別する。
- 最終ソース上の通常再生を竜が左/右の双方で検証。無効化と係数0の候補も再生し、保存traceHash一致を確認。故障コピーを使うテストでは、部分失敗証跡の再生と、竜気/係数/トレース改変の拒否を左右双方で検証した。
- Labテスト197件、TypeScript検査を通過。統合タスクからもゲーム全体777テスト、権利インベントリ14テスト、TS/Viteゲート付きビルドの成功を確認。権利テストは法的クリアランスではない。

### 設定の読み方

すべての設定は実行時ソースをbaselineにする。`dragon-identity.json` / `dragon-broad.json` は変更なし、`dragon-charge-disabled.json` / `dragon-charge-zero.json` は採用値から機構を分離、`dragon-initial-values.json` は初期個体値・技・リーダー・係数を明示復元する。

## 別方策の楽観的タイミング検査

`scripts/balance-lab/probe-dragon-timing.mjs` は、味方がアンカー前に予定する有料攻撃を予測する比較専用コードで、ゲームや通常Labへ読み込まれない。両軍に同じ分岐を適用し、本番の戦闘解決は維持する。ただし敵による中断、目標変化、評価時の防御軽減を無視する楽観的近似であり、人間の最善手や勝率ではない。初期の個体値を明示復元するので採用後も暗黙に候補が変わらない。

純竜の固定8対策512戦で、初期係数7は通常2勝→予測0勝。係数14は52勝→53勝。係数14＋HP220は通常58勝・2引分（11.52%）→予測57勝（11.13%）。対面分布は変わるが、この程度のタイミング予測だけでは初期案を救わない。既存AIを変更する根拠とはしない。実行ソースのハッシュ付き出力は `lab-results/dragon-initial-timing-probe.json`。

## 実行例

```sh
npm run lab:smoke
npm run lab -- run --config configs/balance-lab/dragon-charge-disabled.json --out lab-results/dragon-disabled
npm run lab -- run --config configs/balance-lab/dragon-charge14.json --out lab-results/dragon-charge14
npm run lab -- run --config configs/balance-lab/dragon-broad.json --out lab-results/dragon-broad
npx vitest run src/balanceLabDragon*.test.ts src/balanceLabFamilyWave.test.ts src/balanceLabCli.test.ts
```

再生時は出力レポート内の実在する試合IDを指定する。ソースが変わった場合は元のハッシュと一致するソースでのみ再生できる。採用前の探索と採用後の最終ソース実行を分けて読む。再生が通らない異なるソースを同じ実験として扱わない。
