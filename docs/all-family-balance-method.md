# 全系統システム比較の読み方

この検証は、固定24編成の「毒の初撃1 / 0.5 / 0」と「既存方策 / 同ターンの毒予約を考慮する方策」を分けた比較である。採用の許可や、人間の公平性・面白さの証明ではない。公開版の仕様はこの検証だけでは変更しない。

## 入力・数え方

- 親の事前計画と `all-family-matrix-freeze.json` が編成・枠順・シード・判定基準を固定する。C15の純自然をC17と呼ばない。
- 導出24設定は `all-family-balance-config-freeze.json` にSHA-256と実行予定を記録した。必要12設定は132,096実行。各設定は既存の20,000試合上限以内。
- 主行列は24編成の全276非ミラー組と24ミラー、16シード、両配置。3初撃×2方策で候補の記録行は57,600。ミラーの同一物理配置を一つに数えると55,296試合で、うち52,992は非ミラー。
- 同じ基準対戦の繰り返し、等価設定、ミラーの論理的な左右入れ替えを独立観測の追加と扱わない。全行表示の逆向き行も、新たに実行した別試合ではない。
- 対策確認は固定3案×自然2型に主行列と重複しない64シードを使用。事前の条件が満たされた場合だけ予約64シードを加え、最初の64と合わせた128を別報告する。敗因となった別の基準を帳消しにしない。
- CPUは両側とも本番 `autoOrders` に明示注文させる。予約方策は同じ公開情報だけを使う別群。敵の未公開注文や、最初の毒役が生存して実行する保証は使わない。

## 実効量と潜在量

- 毒の初撃は、ATKを含む基礎全体を係数で変える。0ではダメージイベント自体がなく、最低1HPへの丸めもない。各対象で本来消費した乱数は保持する。
- 直接毒HPと経過毒HPは別々の実際のHP減少。既知の毒6%・残3回・MP16は変更しない。初撃が小さいため毒役・清め・回復・修復が生き残り、経過毒被害が増えることもある。
- 付与を0→3、3→3、1/2→3に分ける。清めまたは毒交換の後の最初の再付与は、ターンをまたいでも別に記録する。これだけで清めが無駄だったとは言えない。
- 清めは実行数・支払MP・消した残回数・実際の回復・余剰回復・ヤヌスの一回分消費を記録する。もともとHP回復が必要だった行動を、全て毒による無駄な手番と数えない。
- 守りの実効量は、その命中だけで守りを取り除き、障壁・同じ乱数・端数処理・命中直前HPを保って再計算した差。観測ダメージを単純に倍算しない。全戦闘の反実仮想ではない。ヤヌス由来の守護寄与は別項目で、二重加算しない。
- 毒交換の上乗せ基礎、失った将来の名目毒、実際の追加HP減少は別々。名目値は、未来の生存・清め・更新を保証しない。
- 20ターンに達しただけでは判定と呼ばない。終了時に両側が生存し、残HP割合で決着した場合だけ実際の判定。20ターン目の全滅決着は除く。

## 保存と再現

`all-family-balance-source/` は拡張前と固定後の完全なソースバイトを保持する。`all-family-balance-packed/` は全予定行の順番、勝敗、トレースSHA-256、両側・全ユニットの資源台帳を可逆圧縮で保持する。各チャンクは65,000バイト以下。フルイベントの木は全試合で複製せず、必要な対戦だけ再生成する。

全行と固定サンプルの厳密な再実行:

```sh
node scripts/balance-lab/verify-all-family.mjs
```

一試合のイベントを再生成（保存済みの実際のIDを使用）:

```sh
node scripts/balance-lab/replay-all-family-packed.mjs SUITE_ID MATCH_ID lab-results/one-full-replay.json
```

ソース・設定・予定表・結果・トレースのハッシュが異なれば再現成功と扱わない。失敗時は既に完了した行と、失敗箇所の初期状態・注文・部分イベント・資源状態を保存する。

## 凍結済みの旧ラベルに関する補足

- 経過毒は「各行動ごと」ではなく、全員の注文された行動を終えた後に各対象へ一回、その後に有限修復という順序。凍結済みの英語定義の “after every action” はこの意味で読む。
- 旧 `cashoutLaterReapplications` は同じターンの交換イベント後の再付与で、消費0回の交換も含む。実際の毒消費後、ターンをまたいだ最初の再付与には新しい `poisonReapplicationsAfterCashout` を使う。
- 旧CLIの “Cashout zero-poison waste” は追加の毒消費が0だった回数だけを指す。基礎攻撃が有用なこともあるため、その行動全部を無駄だったとは判定しない。

これらは測定値の変更ではない。実行と厳密再現に使う凍結済みcore/CLIは変更していない。
