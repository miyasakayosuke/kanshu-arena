# 権利確認を開発ごとに続ける手順

初版: 2026-10-10 / 対象: v0.11 公開プレアルファ候補。法律相談や非侵害の証明ではない。既に配信中のため、正式公開直前だけでなく、変更と配信のたびに点検する。

## 今回の修正

- React / React DOM / Scheduler のMIT著作権表示・許諾条件・免責の全文を配信物へ追加。
- Viteのmodulepreload補助コードと、Vite内のRollup CommonJS変換補助コードも配信物に残るため、対応するMIT全文を追加。
- ゲームから開けるクレジットページ（ライセンス全文のHTML表示付き）と、制作物・端末フォント・ソフトウェアの台帳を追加。
- 新しい依存パッケージ、アートの変更、一部の新規メディア/埋め込みリソース、配信物からの告知漏れをビルド時に検出。

独自コードや画像全体へのMIT等のライセンス付与はしていない。

## 1. 変更時

1. `git diff --stat` と実際の差分を読む。絵、名前、設定、説明文、画面、動き、数値表、音、フォント、依存コード、公開資料の変更を分ける。
2. `asset-manifest.json` に対象ファイル、制作者/制作方法、取得元または着想元、日付、利用範囲、ライセンス、加工、証拠、未確認点を記録する。自作というコメントだけを第三者の権利不存在の証明としない。
3. 独自SVGの変更は実際に描画して見る。参照した特定作品がある場合は、造形・配色・構図・ポーズ・装備・動作・物語・組み合わせを比較し、結果を記録する。名称変更や数値の縮尺変更だけで十分と決めない。
4. 伝承・神話の一般的モチーフと、現代の作家が描いた具体的表現を分ける。現代画像や翻訳文の権利は別に確認する。AI支援による制作でも同じ確認を行い、制作経緯が不明なら未確認と書く。
5. 絵文字は端末の文字描画として使っている範囲を記録する。フォントや絵文字画像の埋め込み・抽出・配布を追加するなら、対象製品の条件を新しく調べる。画面録画・販売用素材への転用も別途検討する。
6. 原作画像、音楽、抽出コード、攻略記事本文、ユーザーコメント等を持ち込まない。出典リンクや公式の動画投稿ガイドラインは別ゲームへの素材利用許諾ではない。
7. DQMSL等を研究資料で正確に言及した事実は残す。配信ゲームのタイトル/宣伝で公式・公認と誤認させる表示は避ける。タイトルや固有名詞は商標調査の課題として管理する。

## 2. 依存関係・告知

- `npm ci` のlockfileで実際の版を確認。実行時依存だけでなく、Vite等が出力する補助コードも調べる。新規/変更ライセンスの条件と配信対象を読む。
- 台帳の `software` を更新し、**確認済み原文**のSHA-256を更新した後に `node scripts/check-rights.mjs --write-notices` でテキスト版とクレジット内のHTML版の全文を一緒に再生成する。ハッシュはレビューの代替ではない。
- 開発専用ツールは `package-lock.json` が版の一覧。ブラウザへ配信しないものを、配信済みの素材と混同しない。node_modulesや開発ツール自体を再配布する場合は、依存全体のLICENSE/NOTICE等を別途保持・確認する。
- 同じ依存名・同じMITでも著作権者や追加通知の変更があり得るため、ライセンス本文を比較する。

## 3. 配信前の確認

```sh
npm run rights:test
npm run rights:check
npm test
npm run build
```

機械チェックの対象は、台帳に記録したパッケージの版/ライセンス全文、独自SVGの変更、現在のロスター絵文字、一部のメディア拡張子/埋め込みパターン、クレジットリンク、`dist`内の告知一致。難読化・動的生成・外部サービス・全文や画面の類似性を網羅しない。新しい取得/描画手段を足す時はチェック自体も更新する。テスト成功を「権利問題なし」と表現しない。

未知の取得元、必要な許可の不足、具体的な類似性の疑い、告知欠落が見つかった新規部分は、そのまま公開せず除外・差し替え・条件確認を行う。既存公開部分に重大な問題が見つかったら、対象と影響を所有者へ知らせ、必要な修正/公開停止を相談する。

## 4. 配信後

- 配信対象の正確なcommit、CIとPages deploymentの成功を確認する。
- 実際のゲームからクレジットを開き、`credits.html` の展開表示で期待した全文を読めることを確認する。`THIRD_PARTY_NOTICES.txt` も公開応答と全文の一致を確認し、確認環境の制限で読めなければその事実を記録する。
- 画面幅とキーボード操作、ゲームへ戻る導線も確認する。
- 下の書式を使い、次回の確認者が追跡できる `docs/rights/releases/` の記録を追加する。

## 記録の書式

```text
日付（UTC）:
リリース/commit:
変更した素材・表現・依存:
確認した出典・版・条件:
実際に比較/描画した対象と結果:
修正/除外した内容:
自動テスト/ビルド結果:
CI/deployment URL:
公開クレジット/告知 URLと取得結果:
残件/担当する次の確認:
専門家の確認: 未実施 / 対象と記録
```

## 5. 専門家への最終確認に用意するもの

`review-ledger.md`、素材台帳、変更履歴、実際の画面/演出、参照と制作過程、公開予定の地域・媒体・収益化方法、依存告知を用意する。外部への資料送付、相談申込み、費用発生、契約締結は所有者の承認を別途得る。正式公開の判断まで未確認事項を継続管理する。
