# 同じ相手で編成を試す導線の連打対策

初回検証: 2026-10-11 UTC。v0.20.1のリリース準備: 2026-10-12 UTC。

## 既存機能と今回の差分

「結果 → 編成を見直して再戦 → 自分の編成を変更 → 同じ相手へ再戦」は既存機能で、確認したv0.19.1の配信用ソースにも存在する。新しいモードや比較機能として追加・宣伝するものではない。

実装前の再現:

1. 一戦を終える。
2. 結果の「編成を見直して再戦」をReactの同じ描画中に2回押す。
3. 同じ相手へ再戦して終える。
4. 「闘技場に戻る → 次の相手」を押す。
5. 同条件再戦の表示が残り、戦数が進まない。次の相手への移動が、古い再戦フラグに影響される。

同じ連打の後、再戦を途中で中断する経路でも古いフラグが残る。修正は結果から編成へ移動する処理で既存の同期ロックを使い、最初の1回だけを受け付ける。ブラウザ履歴の復元中で画面移動が保留された場合は、移動処理の成否を受け取り、ロックと一時フラグを戻す。履歴復元後の再操作や即時再戦を妨げない。既存の再戦開始・新規対戦開始の処理、編成・保存形式、能力値・技・AI・系統・COST・ID・描画・音・依存は変更しない。

## プレイヤー体験とのつながり

黒豆パンの[ロイヤルマスターズ初回の感想（2023-04-30）](https://mamepan.net/entry/royal-masters-1)では、対戦相性による行き詰まりや再挑戦・準備の負担が述べられている。また[2500日目のレビュー（2020-12-22）](https://mamepan.net/entry/2020/12/22/210501)では、編成・相性を考える楽しさと、単調な準備の反復の負担を区別している。

これらは同じ著者の限定的な経験であり、プレイヤー全体の総意や本作の楽しさの測定ではない。今回は、自分で対策を試し、望んだ時に次の相手へ進む既存の操作を壊さない、という小さな改善に絞る。記事本文・画像・原作の具体的な表現はゲームへ持ち込まない。

## 自動検査の受入条件

追加ファイル: `src/App.rematchReliability.test.tsx`（10ケース）。

- 連打後も同じ相手へ1回だけ移動し、その後の「次の相手」で再戦保持が解除され、新しいシードが引かれる。
- 標準戦C17・軽量戦C15の両方で、自分のメンバー入れ替えとリーダー変更を明示的に実行する。変更前と同一の自分編成とは主張しない。
- 敵のID・順序、初期シード、開始オプションが変更前と一致し、敵の初期状態も一致する。別の難易度パラメータはなく、AIとルールを変更していない。
- 消耗した対戦の後でも、再戦は全員のHP/MPがそれぞれの開始時最大値、1ターン目、履歴なしから始まる。指示・自分の編成変更で乱数の消費や結果が変わる可能性は従来通り。
- 3保存枠のシリアライズが変わらず、再戦後に3枠すべてを呼び出してメンバー順とルールを照合する。保存ボタンを押さずに枠を書き換えない。
- 編成プレビューのキャンセルとEscape、編成/受付間のBack・Forward、再戦中のBack後の中断キャンセルを確認する。
- C15でのコスト超過・重複メンバーを候補にできず、編成と保持中の相手が変わらない。
- 連打後の再戦を明示的に中断しても、古い再戦要求を次の対戦へ持ち越さない。
- 結果から再編成と即時再戦を続けて押した場合は、順序を変えても最初の1操作だけを受け付ける。
- Backの補正移動がまだ待機中に中断取消・最終演出完了・再編成要求が続いた場合でも、補正完了後に再編成または即時再戦を操作できる。待機中に却下された要求は、後の「次の相手」へ持ち越さない。

## 実ブラウザで残る確認

v0.20.1の公開確認ゲート。実際に対象コードが配信された後、正確な公開commitを確認してから次を行い、結果をリリース記録へ追記する。

1. モバイル縦画面・横画面で、結果から編成を開き、候補比較の取消、1体の入れ替え、リーダー変更、同じ相手への再戦を操作する。
2. 結果の再編成ボタンを素早く連打し、再戦終了後に次の相手へ進む。二重の画面遷移・保存消失・古い相手の保持がないことを確認する。
3. 3枠を保存して再戦前後にそれぞれ呼び出し、順序とルールを確認する。
4. 再戦準備中と再戦中にBack/Forward、Cancel/Escape、連打を試す。特に破棄済み対戦の履歴へ戻って受付に正規化した後のForwardを実ブラウザで確認する。使用中のhappy-domはreplaceState時に進む履歴を削除するため、この組み合わせのForwardを実ブラウザ相当とは扱わない。
5. 最終公開版の表示・クレジット・第三者告知を別途確認する。

DOM/state検査は実ブラウザのクリック到達性・画面配置・利用者理解や人間の楽しさの合格を意味しない。既存の権利・具体的表現の類似性・専門家確認の未解決事項は残る。
