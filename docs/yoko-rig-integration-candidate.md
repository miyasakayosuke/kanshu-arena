# 妖狐の関節アニメーション：v0.20.7 本編接続

2026-10-12。レビュー済み候補を v0.20.7 へ組み込む記録。基準は v0.20.6 commit `bb78f6c319df500139e5938bca41d6d210e19393` / tree `b65e5ba0273e19534ce388f650742f6962e78647`。候補の作成と公開用の版番号・記録整備は分離した。この記事の検証は公開前までの範囲であり、公開後の実ブラウザ結果とは区別する。

## 変更の範囲

既存ロスター0の妖狐だけ、先に比較用映像で示した新しい絵と関節運動を本編のCanvasへ接続した。頭、左右の耳、三本の尾、前足、まぶた、口、飾りの変換を個別に適用する。図鑑の全身図、48px向けの顔、静止フォールバックは同じパスを参照する。味方ドックの静止表示は維持する。

- `storybookYoko.ts`：共有の新規SVG幾何形状と決定的な姿勢サンプラー。通常表示は外部リクエスト不要のデータURL。
- `storybookYokoRig.ts`：一度だけ動的グループを17枚の静止パーツへ分け、2xの切り詰めた画像を読み込む。ざらつきは静止パーツの作成時に焼き込む。アリーナの同じマウント内で妖狐5体が同じ1組を共有する。
- `storybookYokoBattleMotion.ts`：試作の1120ms動作をそのまま流用せず、本編の800ms着弾・90ms保持・460ms復帰と実impact観測へ写像する。遅延impactが来るまで復帰を始めない。
- `BattleStage.tsx`：準備済みならパーツ描画、未準備または一部失敗なら既存の静止画像経路。静止画像が未読込み/失敗でも全パーツが揃えばリグを描く。世界座標の移動・被弾反動・死体の透明度は従来経路が一度だけ扱う。
- `MonsterArt.tsx`：妖狐だけ共有の新全身図・顔へ変更。全身の縦横比と足元基準位置を明示する。ID1〜36の登録内容は基準版と一致する。

変更していないもの：engine、playback、既存のbattleMotion/originalRosterMotion、能力・技・バランス・RNG・HP/MP・イベント生成・保存編成・Home/図鑑テキスト。他36体は従来描画と従来動作のまま。

## 時刻と状態

攻撃は `actionAge()` が返す既存の時刻を使い、倍率を二重に掛けない。物理と狐火/炎嵐は関節姿勢を分ける。ゼロダメージと毒に新しい直接被弾芝居を付けず、実際のdamageにだけ反応する。倒れた姿勢はunit.keyごとに保持し、effectの掃除で立ち上がらない。HPが戻った再戦、敵入替、マウント解除で古い状態を持ち越さない。

動きを抑える設定は待機を静止させる。世界座標移動と関節揺れを止め、倒れる状態は静止差分で示す。HP/MPのイベント時刻、着弾の確認、演出終了時刻、早送り、スキップの適用方法を変えない。

## 読込み・計算量の上限

- 実体は17レイヤー。片方の口は非表示なので通常1体16 drawImage、5体80 drawImage。コード上の上限は20レイヤー、5体100回。
- パーツの名目RGBA容量は2,399,552 bytes。静止フォールバックやブラウザの内部中間バッファは含まない。コードは8MiBを超える定義を拒否して静止経路へ戻す。
- 描画関数は行列と不透明度だけを変更する。フレームごとのSVG生成、DOMParser、新規Image、デコード、外部通信なし。
- 一部パーツ失敗時にフレームごとの再試行をしない。部分的に頭や尾を欠いた状態へ切り替えず、全パーツが揃ってから切り替える。アンマウントでイベントを解除し、古い完了通知が新しいアリーナを変更しない。
- 以上はコード上の上限と制御された検証結果であり、スマートフォン実機のfps/メモリ合格を意味しない。

## 独立レビューで修正した問題

1. 倒れた後に待機の横幅の呼吸が残っていた。死亡姿勢のbodyXを固定し、離れた壁時計時刻の同一性を検査した。
2. 首の毛の切り抜きが上端で82画素欠けていた。切り抜きをy104まで拡張し、17パーツすべてで輪郭接触と範囲外画素がないことを再確認した。
3. 静止画像の読込みガードが準備済みリグまで隠していた。リグの準備状態を独立させ、静止画像が未完了/失敗の双方でパーツ表示できるテストを追加した。

## 検証と限界

新規18テストで個別行列、5体共有、読込み途中と失敗、再戦、死体保持、動き抑制の途中切替、cleanup、着弾待ち、時刻倍率、変更しない入力イベント、HP/MP/RNGとスキップ再生を確認。既存の全身サイズ期待値は、妖狐の新しい明示寸法だけへ対応させ、他36体の寸法は保持した。

独立担当はSharp/librsvgでパーツを読み込み、実際の `drawYokoRig` を @napi-rs/canvasで実行した。さらにReact+Happy DOMで実際の `BattleStage` をマウントして複数妖狐の待機・攻撃・死亡を描画した。パーツ数、切り抜き範囲、画像生成回数、遅延着弾時の保持、死体保持、rAF解除を確認した。

これはブラウザ、WebKit、実端末、GPU性能測定ではない。文字/フォント描画も実ブラウザの証拠にはしない。実ブラウザ上の縦長・短い横画面、初回画像表示、早送り・スキップ・再戦の確認は公開後の別記録へ残す。重複する妖狐 5 体・画像失敗・動き抑制の制御された自動検証を、UIから再現していない実ブラウザ結果とは扱わない。
