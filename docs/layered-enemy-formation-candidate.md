# 大きな前後配置の敵表示・実装記録

2026-10-12。基準は v0.20.8 commit `e64abcfc251ef5c599f4dbb11d1fdafd482a45e7` / tree `7851e8f405fec1131e299a555d3075636572424a`。

v0.20.9に、別途レビューしたフェンリルリグ・コマンドUIと統合する。本文の既存画像の不変性は前後配置の単独差分を指し、統合版ではフェンリルだけ新しい姿になる。最終集計は release-validation-v0209.json を参照する。

## 変更

- 左からの編成順と各 key を維持し、2・4番を後列、1・3・5番を前列にする。後列から描き、倒れても残りの敵を詰め直さない。
- 基本の大きさは前列1.82倍・後列1.66倍。各素材の縦横比と足元基準を保持し、端や浅い画面では幅・高さの上限を優先する。既存37体の画像そのものは変更しない。
- 名前・HPバー・HP/MP・状態を戦場下の独立した5枠へ移す。枠は左から元の編成順。控えめな足元の番号と対応し、選択中の枠と足元を強調する。HPバーは実際の現在HPを表示し、旧Canvasの遅延HP残像は廃止。
- 敵の絵を押して選べる。描いた画像または各関節パーツの実際の変換行列を保存し、タップ時に手前から透明度を判定する。透けた隙間では見えている後列、重なる不透明部分では前列を選ぶ。戦闘不能・対象外の手前の姿を貫いて後ろへ誤選択しない。
- 透明度は最初に必要になった時だけ最大256pxの一時Canvasから読み、1ピクセル1バイトで画像ごとにキャッシュ。追加Image・画像の再ロード・毎フレームのピクセル読出しをしない。読出し非対応やSecurityErrorでは背後を選ばず、名前付き44px以上の枠を使える。
- 数値・着弾・全体効果の位置は同じ配置情報へ合わせ、戦闘中のリサイズでも更新する。関節リグと通常画像は同じ拡大変換内に置く。
- 短い縦画面と幅619px以下の短い横画面では全幅の一つのスクロールを使用する。幅620px以上の短い横画面は既存の左右構成を保持する。Canvas140pxと状態行の内容高さを親グリッドで確保する。

## 統合時のフェンリル調整

新しい17パーツのフェンリルを拡大配置へ接続した追加レビューで、浅い戦場の着弾直前に前足が下端からはみ出す例を検出した。ID12だけ既存の移動距離を60%へ調整し、同じ移動曲線・連撃の揺れ・持ち上がり・傾き・関節姿勢・着弾時刻を維持する。ピクセル選択は調整後の実際の描画行列を使う。他の36体の移動、ゲーム状態とイベントは変えない。全5枠と3つの浅い戦場で実Canvasの輪郭境界を再確認する。

## 検証と境界

`enemyFormation.test.ts` は37体と更新予定のフェンリル比率、前後順序、足元、縦横比、上下左右の収まりを検証する。`enemyHitTest.test.ts` は重なり、透明な隙間、DPR・回転・拡縮・関節変換、戦闘不能の遮蔽、キャッシュ上限、読出し失敗と未読込を検証する。既存の画像キャッシュ・妖狐リグ・戦闘演出テストは配置変更に合わせて期待値を更新し、エンジン側のテストは変更していない。

独立した実Canvas描画では、全37体と動く妖狐5体を含む558,900箇所のピクセル選択と3,330通りの素材・枠・画面比率を検査した。小さい輪郭の判定差は最大256pxの透明度マスクに伴う輪郭付近のもの。これを実機の操作確認・fps・ブラウザメモリ合格とは扱わない。

実ブラウザでは400×606、326×432、802×394に加え500×394・620×394の境界で、名前/HPと対象枠、後列の頭へのタップ、前列との重なり、Tabによるフォーカス、長い状態表示と味方/コマンドへのスクロール、スキップ・再戦・高速再生を確認する。公開は担当者が正確な統合版のCI・Pages・画面確認と前版への復旧手順を揃えて行う。
